## 1. PERSISTENCE (P0) — full session / OR AST survives restart

### Schema finding (reported before forcing a fit)

`CiPolicyDocument` / `ci_policy_document` holds `source_text` + `metadata` only — **not** underwriting rules, expression AST, or parameter bindings.  
`ci_policy_rule_candidate.expression` can hold AST but requires `clause_id NOT NULL` and does not cover the full `PolicyStudioSession` aggregate.

**Schema addition:** Flyway `V121__policy_studio_session_snapshot.sql` → table `ci_policy_studio_session_snapshot` (`policy_document_id` PK/FK → `ci_policy_document`, `payload jsonb`).

### Before

- `PolicyDocumentService.create` / upload built in-memory `CiPolicyDocument` only.
- Restart → `GET …/documents/{id}` → **404** `Policy document session not found`.
- Items **98–100** failed on this definition.

### After (staging proof on `3d166fc`, dirty=false)

| Step | Result |
|------|--------|
| NORMAL upload (`kind=upload`, `demo=false`) | HTTP 200, doc `d1d940a3-839c-45de-a024-67f061a6ec18` |
| Preview/confirm explicit OR | `complete=true`, `op=OR`, confirmed |
| DB | `ci_policy_document` count=1 for id; snapshot `plen=22187` |
| Logs | `durable session committed … rules=5` |
| `docker compose restart los-core` | healthy |
| GET by documentId | **HTTP 200**, `hasOr=true`, `uwCount=2` |

Root causes fixed along the way (not left as “overlay-only”):

1. Orchestrator used `new PolicyStudioPersistenceService()` — Spring JPA never wired (`9e2093b`).
2. Pre-assigned UUID + `@GeneratedValue` → Spring Data merge / Hibernate `EntityExistsException` on persist (`3d166fc` Persistable + no `@GeneratedValue`).
3. Durable write isolated in `PolicyStudioSessionDurableWriter` (`REQUIRES_NEW`) so JPA failures cannot `UnexpectedRollback` the upload TX.
